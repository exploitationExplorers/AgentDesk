# 宝塔部署流程

1. 用 `deploy.list` 找到与用户描述匹配的配方；匹配不唯一时列出候选让用户选，不要猜。
2. 部署前用 `projects.status` 检查本地项目：有未推送提交（ahead > 0）时提醒用户先 push，否则服务器拉不到新代码。
3. 向用户复述将执行的步骤，然后调用 `deploy.run`（会弹出审批）。
4. 结果解读：
   - 终端步骤失败：看最后几行日志，区分 git 冲突、依赖下载失败、编译错误、磁盘空间不足。
   - 重启步骤失败：多为宝塔项目名与配方不一致，或页面改版导致按钮定位失败，建议在部署中心更新配方或重新录制。
   - 健康检查失败：服务可能仍在启动，建议等 30 秒后从失败步骤重试；持续失败则查看宝塔项目日志。
5. 需要人工登录（验证码）时，告诉用户在弹出的浏览器窗口完成登录，部署会自动继续。
