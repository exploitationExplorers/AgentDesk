# 三方向交叉复核与实施优先级

复核日期：2026-10-28。输入为 `core.md`、`interaction.md`、`integrations.md`；结论描述本轮分析及随后的局部实施，不代表全部差距已经完成。

## 覆盖一致性

三个分工的文件数量为 376 + 749 + 777 = **1,902**，与全量 `source-inventory.json` 一致。目录所有权没有缺口；MCP/LSP 等跨域关键文件允许重复深读，但不会重复增加覆盖数量。

行数采用不同统计口径：交互报告去掉 455 个文件中的单行内嵌 source map，三个分组的行数和比全量物理行数少 455 行。这是统计口径差异，不是漏读 455 行业务代码。对外应以文件数说明目录覆盖，并分别说明“全文件结构扫描”和“关键路径深入阅读”，不宣称 50 万行都已逐行语义审计。

三份报告一致识别出参考材料的边界：缺少完整构建配置，部分相对导入目标缺失，存在 stub、功能开关、内部账户和外部服务依赖。因此不将目录中出现的功能名全部算作官方发布版可用功能。

| 会话与长期记忆       | MemoryService 的事实/偏好召回已存在；它不替代长会话压缩、结构化工具历史或工作区规则。三项应分别建设。                                         |
| 任务与后台进程       | 已有 Task/Run、排队、取消和子运行；不等同于主对话可继续的后台 shell handle、可恢复队友以及任务依赖图。                                        |
| 审批与沙箱           | 单次批准、权限持久规则、项目路径约束、OS 进程沙箱是不同层次。收紧 shell 分类不能宣称已有 OS 沙箱。                                            |

## 优先级

1. **先保障正确性和现有流程。** 单次欢迎区、严格 TS 类型、工具顺序屏障、shell 明确分类、跨端审批、审批等待退出和项目工作区隔离。这些都能用局部回归测试验证，且直接影响用户现在使用的流程。
2. **再补编码任务的持久上下文与恢复。** 工作区项目指令、标准技能字段兼容、按模型窗口压缩、文件分段读取、读取版本校验、修改检查点和冲突安全回退。上下文压缩与文件回退的后端先行，界面随后。
3. **提升高频交互效率。** 本地 `/help`、`/new`、`/resume` 命令，输入历史、多行编辑、可回答的文本问答、按文件聚合修改、运行中追加指令。命令与普通模型提示应分流，避免把 UI 操作交给模型猜测。
4. **独立建设生态与并发工作空间。** MCP、LSP、Hooks、动态子 Agent、后台进程、worktree 隔离、跨设备远程、插件分发。按可观察验收逐项落地，不合并成无法核验的“完整对齐”承诺。

## 本轮交互实施检查点

- 交互目录的业务源码迁移为 TS/TSX，复用 shared 事件、Task、Approval 和 Agent 类型；没有引入 `any` 或关闭严格检查。
- 聊天与任务视图共用审批等待器，移除 abort 监听、停止重复轮询请求；远端批准/拒绝不再重复 POST。
- inspect 快照中的当前待审批可直接恢复并跨端同步，不依赖 SSE 重放；已结束 Run 和同 Run 内非当前审批不再索取输入，缺少最终决定时显示“已处理或已结束”。
- 任务待审批时 Ctrl+C 能退出跟随而不取消后台任务；工具展开统一 Ctrl+O，支持实时工具输出。
- 4 个交互/状态机测试文件也迁为 TS；51 个定向测试通过，包括延迟历史加载后的单次欢迎区、远端批准/拒绝、快照审批恢复、历史审批不遮蔽当前审批及不吞掉 Ctrl+O、待审批退出。CLI 的源码和测试类型检查、交互范围 ESLint 已通过。
- `/help`、`/new`、`/resume`、文本问答和代码回退仍是明确缺口；本轮没有为它们添加没有后端支撑的入口。

最终验证数量及其他方向的实施结果由主任务汇总，避免将分析建议误写为已实现能力。
