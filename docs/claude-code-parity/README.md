# AgentDesk 与 Claude Code 的能力对照及本轮改进

核查日期：**2026-10-28**。本次围绕三个目标开展：修复终端重复欢迎区，系统梳理本地 Claude Code 参考源码的能力差距，以及把可迁移的 JavaScript 源码纳入 TypeScript 严格检查。

AgentDesk 已经具备原生代码修改、任务执行、审批和桌面“编码现场”的基础链路。本轮重点补齐现有流程的可靠性，并建立可追溯的功能对照。**这不代表已经实现 Claude Code 的全部能力。** 上下文压缩、代码检查点回退、MCP、LSP、完整插件系统等仍需要独立建设。

## 重复欢迎区的原因和修复

这确实是渲染缺陷：启动时聊天界面的 `Static` 先输出欢迎区；异步历史列表返回后切换到会话选择器，选择器又渲染一次欢迎区；随后进入聊天还可能重新挂载静态输出树。终端保留了已经写入的静态内容，于是出现重复角色和标题。

现在欢迎区与历史输出使用同一棵稳定的树，选择器只切换动态区域。回归测试特意延迟历史接口响应，分别验证选择“新建”和“恢复旧会话”之后，`AgentDesk v…` 标题仍只有一次；测试目录名也包含 AgentDesk，避免误把路径文字当成第二个标题。

执行内核也修复了轮次耗尽时的完成判定：达到 `maxTurns` 后若模型仍请求工具，执行完本轮允许的工具便报告任务尚未完成，保留已产生的结果和事件，不启动额外一轮或发送正常完成事件；最后一轮直接回答仍可正常成功。`maxTurns` 必须为正整数。这避免将中断的编码任务误标成成功。

技能的 `user-invocable` 目前保留为元数据；没有相应命令菜单和显式调用入口时，不宣称已实现这一交互能力。`allowed-tools` 字段兼容也不等于提供 OS 沙箱或强制工具权限隔离。

已有桌面“编码现场”继续通过 Task/Run 事件展示工具活动、命令输出、文件 Diff、审批和追加指令。它显示本产品运行时记录的可观察操作，不展示模型内部推理；外部 Claude 进程的所有内部步骤也不会凭空变成本产品的原生文件事件。

## 为什么仍可能看到 JS 或 MJS

迁移前，CLI 中大量 `.mjs`、`.jsx` 是业务源码，而原来的 tsconfig 只包含 `.ts`，这些文件没有获得与项目其余源码相同的类型检查。本轮迁移同时更新了组件参数、事件联合类型、API 响应、状态机、入口引用和测试，不是只改扩展名。

按 Git 跟踪文件统计，共 **42 个原有 JS/MJS/JSX 文件迁移到 TS/TSX**；此前新增的欢迎组件也已迁移。删除两个旧 JSX 加载器，改用明确的 `tsx` 开发入口。保留的两个原生 Node 测试入口及用途见 [CLI README](../../apps/cli/README.md#typescript-开发入口)。

构建生成的 `dist/index.mjs`、`dist/runtime.mjs` 等仍应保留 JavaScript：它们是 Node.js 执行和发布的 ESM 产物，来源已经是 TypeScript。工具要求使用的 JS 配置文件、第三方依赖、临时调试产物也不应机械改名；判断标准是是否属于我们维护的可迁移源码，以及修改后能否继续按约定启动。

源码中的 `import "./module.js"` 也不说明还存在同名 JS 源文件。TypeScript/构建器可将这种 ESM 导入解析到 `.ts/.tsx`，构建后则对应 JavaScript 模块。

## 源码到底看到了什么范围

本地材料来自：`D:/AI code/claude-code-2.1.87/claude-code-2.1.87/src`。

- 全量目录清单覆盖 **1,902 个文件**。三个分工文件集合的并集与总清单一致，没有未分配的源码文件。
- 全部文件进行了内容读取后的结构扫描，提取模块职责、导出符号、功能开关及相关入口；执行、编辑、权限、压缩、输入、会话恢复、扩展与远程等关键路径进一步阅读实现和调用关系。
- **结构覆盖不等于对约 51 万行代码完成逐行语义审计。** 本轮没有构建或运行这份参考材料，也没有把参考源码直接复制进项目。

- 发现 **18 个禁用且隐藏的 command stub**；其余功能还可能受条件编译、账户和远端服务限制。不能把每个文件名都列成一个默认可用功能。
- 部分 TSX 带 React Compiler 转换和内嵌 source map；交互分析解码了其中 455 个 source map 做结构复核。不同报告的行数口径因此略有差异，文件覆盖数量一致。

## 后续对齐的实施顺序与验收

| 阶段                   | 能力                                                              | 完成时应看到的行为                                                                          |

| 下一阶段：日常编码会话 | 输入历史、多行编辑、`/help`、`/new`、`/resume`、文本问答          | 正常字符不被快捷键吞掉；本地命令不调用模型；待回答的问题能提交文本；busy 时的输入有明确反馈 |

| 下一阶段：修改恢复     | 分段读取、读取版本账本、文件检查点、代码/会话独立回退             | 外部修改后拒绝陈旧覆盖；回退前可审阅影响；不覆盖用户在 Agent 修改后继续写入的内容           |
