pi：组件 / 主题体系（从目录结构归纳）

约定pi 的做法AgentDesk 现状
Selector 家族model/theme/session/config/trust/thinking/oauth/tree-selector 统一命名与交互部分具备 有 Select 组件打底，但审批菜单、会话选择器各写各的
主题即数据dark.json/light.json + schema 校验 + ThemeController + 可安装主题包缺失 theme.ts/colors.ts 是写死的 TS 常量
消息按类型拆组件assistant/user/tool-execution/compaction-summary/skill-invocation 各一个组件文件部分具备 StepRow/ApprovalCard 已拆分，但压缩摘要、技能调用无专属视觉表达
最小粒度反馈组件countdown-timer/bordered-loader/status-indicator/keybinding-hints/dynamic-border缺失 多数反馈内联写在 TaskView/App.tsx 里
富内容内联渲染diff / mermaid / markdown-transform部分具备 已有 diff 展示，无终端内 Mermaid 渲染
终端渲染架构差分渲染，不依赖 React，OKLab 色彩插值架构不同 Ink（React 虚拟 DOM 渲染到终端），当前功能够用
血缘提示：AgentDesk 已依赖的 @mariozechner/pi-ai 与本节的 @earendil-works/pi-ai 是同一作者（Mario Zechner）同一套库的不同阶段——参考 pi 不是引入陌生理念，而是看清楚已经在用的底层库后来演进成了什么样。

落地建议：分阶段，不是一次性重写

阶段范围现状差距建议
1桌面端动画基建零动画库引入 motion（Framer Motion 继任者），先覆盖本周期新增的 ArtifactWorkspace/SessionPanel/ConversationList
2桌面端动效词汇表无统一命名规范参照 magpie 四分类，在 packages/ui 建立共享 motion 预设
3CLI 主题结构写死的 TS 常量拆成 token 数据 + ThemeController，为未来自定义配色留口子
4CLI 组件信息架构交互各写各的梳理 Selector 家族统一接入点；压缩摘要/技能调用拆独立展示组件
5（中长期）CLI 渲染架构Ink vs 差分渲染不在本轮动手；记录为性能瓶颈出现时的候选方向
6（中长期）状态可视化图谱无此类组件有需求时再做，复用阶段 2 的动效词汇表

关键发现

  • 不是做错了，是从没建设过：CLI 和桌面端功能完整，但动效/主题系统都停留在朴素默认值，没有被当成独立设计系统投入过。
  • “移植”要拆成两层：视觉语言/组织方式（可以搬）vs 具体渲染技术（magpie 的 vanilla JS、pi-tui 的差分渲染，都和 AgentDesk 的技术栈不兼容，不能搬）。
  • pi 不是外部项目，是自家依赖的未来形态：参考它的组件体系本质是向自己已经选用的库的后续演进学习。
  • 四个阶段可以现在排期，两个方向需要单独立项：避免把"参考里有"直接当成"现在就该做"的授权。
